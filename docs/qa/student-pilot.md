# 학생 사용성 검증안

상태: **실행 전**. 자동 테스트나 개발자 확인은 학생의 재사용 의사를 입증하지 않습니다.

## 가설과 대상

성심교정 신입생·편입생·복학생이 공강 중 장소, 식사, 공부할 곳을 찾을 때 학교 홈페이지를
여러 번 탐색하는 수고를 줄일 수 있다는 가설입니다. 핵심은 기능 수가 아니라 **정확한 다음 행동**입니다.
API/MCP는 이 정보를 다른 도구에서도 같은 출처와 신뢰 수준으로 재사용하는 기반입니다.

## 1차: 5–8명, 각 15분

운영자가 자발적 참여자를 직접 모집합니다. 학과·동아리 채널은 운영자 허락을 받고 사용하며
이 저장소나 에이전트가 연락·홍보를 대신 보내지는 않습니다. 개인정보 없이 익명 ID만 기록합니다.

1. 기존 방법으로 보건실 위치·전화 찾기 → 이 앱으로 같은 목적 달성하기. 순서는 참여자별 교차합니다.
2. K관과 카페 멘사를 찾아 건물과 층을 설명하고 길찾기 화면까지 이동합니다. 실제 전화는 걸지 않습니다.
3. 오늘과 다음 영업일 메뉴를 구분합니다. 주말·메뉴 없음 상태도 보여줍니다.
4. 좌석 조회 실패·오래된 시간표 화면에서 현재 자리 유무를 어떻게 이해하는지 묻습니다.
5. 실시간 좌석과 시간표상 예상 공실의 차이를 자기 말로 설명하게 합니다.

말로 유도하지 않고 성공/실패, 첫 행동까지 걸린 시간, 되돌아감, 잘못 이해한 문장을 기록합니다.
위치의 건물 입구·실내 동선 정확성은 실제 현장에서 별도 확인해야 합니다.

## 2차: 7일 사용

선택적 홈 화면 추가 안내만 제공하고, 매일 사용을 재촉하지 않습니다. 7일 뒤 어떤 실제 상황에서
다시 썼는지, 기존 대안으로 돌아간 이유가 무엇인지 묻습니다. 재방문이 있었는지와 단순 링크 클릭을 구분합니다.
현재 외부 분석 SDK·위치 추적·사용자 식별자는 추가하지 않았습니다. 수동 기록을 우선합니다.

## 진행/축소 기준 — 검증 전 가설적 기준

- 8명 중 6명 이상이 장소→층/호수→길찾기를 도움 없이 완료할 것.
- 오래된 좌석을 현재 좌석으로, 예상 공실을 개방 보장으로 이해한 사례는 **0건**을 목표로 합니다.
- 기존 방법 대비 시간을 줄이지 못하면 홈 정보량·검색어·행동 버튼을 먼저 조정합니다.
- 자연 재사용이 없으면 홍보 확대보다 식사/공간/위치 중 실제 반복 문제가 있는 한 흐름으로 축소합니다.
- API/MCP 채택은 도구 호출 수가 아니라 정상 완료된 질문, 정정 필요 여부, 출처 재확인으로 평가합니다.
- 무료 호스팅의 첫 조회 지연이 반복 포기의 원인이면 유료 전환 비용을 제시해 사용자 승인을 받습니다.

## 참고한 제품 패턴

- [UCL Go](https://www.ucl.ac.uk/isd/services/websites-apps/ucl-go): 학생의 반복 업무를 묶는 접근. 우리도 모든 안내를 홈에 나열하기보다 핵심 행동에 집중합니다.
- [Kakao 지도 가이드](https://apis.map.kakao.com/web/guide/): 목적지만 전달하고 실제 경로 선택은 전문 지도에 맡깁니다.
- [MCP tools 규격](https://modelcontextprotocol.io/specification/2025-11-25/server/tools): 도구의 읽기 전용 의도와 구조화된 결과 계약을 명시합니다.

참고일: 2026-09-06. 타 서비스의 존재나 기능은 이 프로젝트 수요의 증거가 아닙니다.
